# One command table for the window

Status: built.

## Problem

A window command is described in up to five places, keyed by an `"app.x"` string:
`actions.rs` `SIMPLE` (handler), `keys.rs` `BINDINGS` (keys), `command_palette.rs`
`COMMANDS` (palette label), the header-bar tuples and menu in `window.rs`, and the lists
and buttons in `empty.rs`. `term_menu.rs` repeats labels too. Adding a command takes 3
or 4 edits, labels drift ("Settings" and "Preferences" for one action), and a mistyped
name fails silently. `term_menu.rs` binds "Cut" to `app.copy`, a bug the strings
allowed.

GTK can't be the source on its own: handlers are Rust, GtkBuilder has no app
accelerators, and names in `.ui` files aren't checked at build time. So the table is
Rust, and once installed, every surface reads through GTK.

## Usage (caller's view)

```rust
use crate::commands::Cmd;

// window.rs: the header lists commands. Icon, action and tooltip come from the table.
for cmd in [Cmd::ToggleSidebar, Cmd::SplitRight, Cmd::Cut, Cmd::Copy, Cmd::Paste] {
    let b = gtk::Button::from_icon_name(cmd.icon());
    cmd.bind(&b);                                   // action name + "Split Right · Ctrl+\"
    bar.pack_start(&b);
}
leave.append_item(&Cmd::Quit.menu_item());

// empty.rs: a short label where the surface wants one.
let b = gtk::Button::with_label(Cmd::OpenFinder.short());   // "Open File"
Cmd::OpenFinder.bind(&b);

// term_menu.rs
for cmd in [Cmd::Copy, Cmd::CopyClean, Cmd::Paste] { menu.append_item(&cmd.menu_item()); }
menu.append_item(&Cmd::OpenPathEditor.menu_item_for(&path));

// command_palette.rs
for cmd in Cmd::palette() { /* title cmd.label(), badge cmd.chord() */ }

// find.rs and other hints
Cmd::FindNext.chord().unwrap_or_default()

// startup: accelerators first, then the actions.
crate::commands::install_accels(&gtk_app);
crate::commands::install(&app);
```

Adding a command is one block in `commands.rs`. Callers write `Cmd::X`, never `"app.x"`,
so a wrong name is a compile error. Placing a command on the header or the empty page is
a second, deliberate edit in that layout file.

## Shape

`crates/xenon/src/commands.rs`, replacing `keys.rs`, `SIMPLE`, `COMMANDS`,
`string_action`, `install_hidden_files`, `palette_passes`, `install_palette_keys`,
`App::chord`, `App::tip` and the two actions in `remote_ui::install`.

```rust
commands! {
    NewTerminal = "new-terminal" => Spec {
        label: "New Terminal", icon: "utilities-terminal-symbolic", keys: &["<Control>n"],
        ..Spec::run(|a| a.new_terminal())
    },
    OpenFinder = "open-finder" => Spec {
        label: "Go to File…", short: Some("Open File"), keys: &["<Control>p"],
        launcher: InLauncher::Step(1),
        ..Spec::run(|a| a.open_finder())
    },
    ShowHiddenFiles = "show-hidden-files" => Spec {
        label: "Show Hidden Files",
        ..Spec::toggle(|a| a.sidebar.files.shows_hidden(), |a, on| a.sidebar.files.set_hidden(on))
    },
    OpenPathEditor = "open-path-editor" => Spec {
        label: "Open in Editor", palette: false, ..Spec::path(|a, p| a.open_path_editor(p))
    },
    // ...
}

/// Generated by `commands!`: the enum, `Cmd::ALL`, `name()`, `action()` ("app." + name),
/// and a private `spec()` match that covers every variant.
pub(crate) enum Cmd { NewTerminal, OpenFinder, /* ... */ }

pub(crate) struct Spec {
    label: &'static str,
    short: Option<&'static str>,
    icon: &'static str,
    keys: &'static [&'static str],
    palette: bool,                 // default true
    launcher: InLauncher,          // what the key does while the palette is open
    run: Run,
}

enum Run {
    Plain(fn(&Rc<App>)),
    Toggle { initial: fn(&App) -> bool, set: fn(&Rc<App>, bool) },
    Path(fn(&Rc<App>, &Path)),
}

pub(crate) enum InLauncher { Blocked, Runs, Step(i32) }

impl Cmd {
    pub fn label(self) -> &'static str;
    pub fn short(self) -> &'static str;          // short label, else label
    pub fn icon(self) -> &'static str;
    pub fn chord(self) -> Option<String>;        // first accel from accels_for_action, as a label
    pub fn tip(self) -> String;                  // "Label · Chord"
    pub fn bind(self, w: &impl IsA<gtk::Actionable>); // action name + tooltip
    pub fn menu_item(self) -> gio::MenuItem;
    pub fn menu_item_for(self, path: &Path) -> gio::MenuItem;
    pub fn palette() -> impl Iterator<Item = Cmd>;
}

pub(crate) fn install_accels(app: &gtk::Application); // set_accels_for_action, first
pub(crate) fn install(app: &Rc<App>);            // gio actions, once
```

- The table holds what a command is. Where it appears (header order, menu sections,
  empty-page lists) stays in the file that draws it, as `[Cmd; N]` arrays.
- `chord()` reads the keys back from GTK after `install_accels`, so the keys have one
  owner.
- The launcher's block, pass-through and redirect rules become the `launcher` field.
- Done check: `rg '"app\.'` in `crates/xenon/src` finds only `commands.rs`.

## Synthesis decision

Both sketches reached a Rust table generated by a small `macro_rules!`. Sketch A was the
base for its `Spec` fields (`short`, `icon`, `launcher`) and `bind()`. From sketch B
came reading keys back from GTK instead of the table, and `gio::Menu` items for menus.
Sketch A's build-time checks for duplicate keys were dropped as more code than the risk
warrants.

## Tradeoffs accepted

- We accept one macro in exchange for one edit per command and build-time names.
- We accept that a duplicate accelerator is not caught at build time. GTK takes the last
  one.
- We accept that layout lists still name commands. A command doesn't appear on the
  header by being added to the table.

## Alternatives considered

- GtkBuilder `.ui` menus as the source: names become unchecked strings again, and
  there's still no place for app accelerators.
- A plain enum with a hand-written `match` and a hand-kept `ALL` list: a second list.
- Per-surface flags in the table: they can't express order.

## Decisions

- The settings action is "Settings" everywhere.
- `app.quit` is "Close Window" everywhere, since terminals keep running.
- `browse-workspace` and `remote-toggle` are deleted.
- `adw::ShortcutsDialog` on Ctrl+? lists every shortcut, built from the table.
- Add a Save As command (Ctrl+Shift+S). The editor's changed-on-disk banner offers it.
